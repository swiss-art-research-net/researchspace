Semantic data table

The semantic-data-table component is a modern table component for SPARQL SELECT results. It supports the core features of semantic-table while adding grouping, aggregation templates and column-level filtering.

Use it when you need a richer table interface with grouped rows, aggregated summaries or more structured filtering controls.

Examples

Custom Column Configuration and Cell Templates

Column headers can be customized and individual columns can render their cells using Handlebars templates.

PREFIX rdfs: SELECT ?person ?label ?gender WHERE { VALUES (?person ?label ?gender) { (person:alice "Alice" "female") (person:lisa "Lisa" "female") (person:martin "Martin" "male") } }' column-configuration='[ { "variableName": "person", "displayName": "Person", "cellTemplate": "{{label.value}}" }, { "variableName": "gender", "displayName": "Gender" } ]'> ]]>

Global and Column Filtering

The component supports both a global search field and optional column filters. Column filter type can be inferred automatically or set explicitly using filterType.

SELECT ?person ?gender ?age WHERE { VALUES (?person ?gender ?age) { (person:alice "female" 34) (person:lisa "female" 10) (person:carol "female" 22) (person:martin "male" 26) (person:max "male" 17) } }' options='{ "showFilter": true, "showColumnFilters": true }' column-configuration='[ {"variableName": "person", "displayName": "Person", "showFilter": false}, {"variableName": "gender", "displayName": "Gender", "showFilter": true, "filterType": "select"}, {"variableName": "age", "displayName": "Age", "showFilter": true, "filterType": "number"} ]'> ]]>

Grouping and Aggregation

Rows can be grouped by one or more columns using groupingOptions.groupedBy. Aggregated cells can use built-in aggregation modes such as average, count or concat.

SELECT ?person ?gender ?age WHERE { VALUES (?person ?gender ?age) { (person:alice "female" 34) (person:lisa "female" 10) (person:carol "female" 22) (person:eve "female" 31) (person:martin "male" 26) (person:max "male" 17) (person:bob "male" 41) } }' options='{ "enableGrouping": true, "groupingOptions": { "groupedBy": ["gender"], "expandByDefault": true } }' column-configuration='[ { "variableName": "person", "displayName": "People", "aggregation": "concat", "aggregationCellTemplate": "People in this group: {{rows.length}}" }, { "variableName": "gender", "displayName": "Gender" }, { "variableName": "age", "displayName": "Age", "aggregation": "average", "aggregationCellTemplate": "Average age: {{value}}" } ]'> ]]>

Grouped Row Templates

groupRowTemplate and groupMemberRowsTemplate can be used to customize the visual rendering of grouped rows. The table continues to define the data model: columns, headers, grouping, sorting, filtering, expansion and pagination are configured through column-configuration and options. The row templates only affect how grouped rows and their expanded member rows are displayed.

groupRowTemplate defines the grouped summary row and is evaluated once for each group. groupMemberRowsTemplate defines the expanded members of a group and is also evaluated once for each group, not once for each member row. The template receives all member records in rows, so members can be rendered by iterating over {{#each rows}}. Both templates are optional and independent. The groupRowTemplate receives rows, cells, isExpanded, groupByValue and memberCount. The groupMemberRowsTemplate receives rows, groupByValue and memberCount.

By default, the table renders a built-in expand/collapse toggle next to groupRowTemplate. Set showGroupRowToggle to false to hide this toggle. To provide a custom toggle inside the template, add the rs-row-toggle class to an element in groupRowTemplate. Set toggleGroupRowOnClick to true to make clicking anywhere in the grouped row toggle expansion. Interactive elements (links, buttons, form fields) inside the row keep their normal behavior and do not toggle the group unless they have the rs-row-toggle class.

SELECT ?person ?label ?team ?age WHERE { VALUES (?person ?label ?team ?age) { (person:alice "Alice" "Research" 30) (person:bob "Bob" "Research" 36) (person:carol "Carol" "Research" 42) (person:dan "Dan" "Design" 28) (person:eve "Eve" "Design" 40) (person:frank "Frank" "Engineering" 38) (person:grace "Grace" "Engineering" 50) (person:henry "Henry" "Editorial" 33) } }' number-of-displayed-rows="2" options='{ "enableGrouping": true, "showTableHeading": false, "groupingOptions": { "groupedBy": ["team"], "expandByDefault": true, "groupRowTemplate": "{{> groupRowTemplate}}", "groupMemberRowsTemplate": "{{> groupMemberRowsTemplate}}", "showGroupRowToggle": false, "toggleGroupRowOnClick": true } }' column-configuration='[ {"variableName": "team", "displayName": "Team"}, {"variableName": "person", "displayName": "Person"}, {"variableName": "label", "displayName": "Label"}, {"variableName": "age", "displayName": "Age", "aggregation": "average"} ]'> ]]>

Custom Tuple Template

A tupleTemplate can be used to render each row using a custom layout instead of the default table cell output.

SELECT ?person ?label ?gender WHERE { VALUES (?person ?label ?gender) { (person:alice "Alice" "female") (person:lisa "Lisa" "female") (person:martin "Martin" "male") } }' tuple-template='
{{label.value}}
{{gender.value}}
'> ]]>
